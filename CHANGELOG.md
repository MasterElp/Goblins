# Changelog

## [Unreleased]

### Добавлено
- Документы `docs/02_CorePrinciples.md`, `04_WorldModel.md`, `05_Entity.md`, `06_GameLoop.md`, `07_TechStack.md` — фундаментальные законы, модель мира, ECS, игровой цикл, технологический стек.
- `core`: `World` (ECS-хранилище + Area), `Area` (тайловая карта 100x100, хранение по тайлам, индекс непроходимости), `PositionComponent`, `ImpassableComponent`, `TimeComponent`, `CommandQueue`, `System`, `GameLoop` (фиксированный порядок систем, delay между тиками).
- `core`: шаг генерации мира `scatterBoulders` — случайное размещение непроходимых булыжников без коллизий по тайлам.
- `server`: WebSocket-слой (`NetworkServer`, IXWebSocket + nlohmann/json) — полный снапшот мира при подключении клиента, рассылка номера тика после каждого тика.
- `clients/desktop`: консольный клиент на чистом C++ — ASCII-отрисовка карты, прокрутка (WASD), отображение текущего тика. Подключается только по WebSocket-протоколу сервера, без доступа к core.
- `CHANGELOG.md`.

### Изменено
- Десктопный клиент переписан на чистый C++ (терминальный рендер вместо GUI-фреймворка) — минимум зависимостей, ничего дополнительно устанавливать не нужно.
- Все зависимости (EnTT, nlohmann/json, IXWebSocket) перенесены из CPM.cmake в единый корневой `third_party/` — ни один CMake-проект в репозитории (ни server, ни client) больше не обращается к сети. `third_party/CMakeLists.txt` — общее описание сборки библиотек для core/server и клиента, без дублирования кода и конфигурации в двух местах (раньше у клиента была своя отдельная копия).
- Исполняемые файлы переименованы: `goblins_server` → `server`, `goblins_desktop` → `client`.
- Весь консольный вывод (server и client) переведён на английский — чтобы не зависеть от кодировки консоли на Windows.
- Адрес, порт, размер Области, число/seed булыжников, интервал тика, число тиков и параметры окна просмотра клиента вынесены в единый `config.json` (читают и сервер, и клиент) — общий код чтения в `shared/config/Config.hpp`, подключается обоими проектами так же, как third_party. Адрес по умолчанию — `127.0.0.1`. По умолчанию сервер тикает бесконечно (`tick_count: -1`).
- Добавлены `build.ps1`/`run.ps1` (Windows, PowerShell) как основной способ запуска на Windows — `run.sh` через Git Bash (mintty) не даёт клиенту настоящую Win32-консоль, из-за чего вместо перерисовки экран просто скроллится; `.sh`-скрипты оставлены для Linux/macOS/WSL.
- Десктопный клиент переписан с консоли на графическое приложение (raylib, vendored в `third_party/raylib`) — окно с отрисовкой тайлов/булыжников, HUD-панель с номером тика и координатами просмотра, плавная прокрутка WASD/стрелками вместо ASCII-рендера.
- Конфигурация разделена: `ServerConfig` и `ClientConfig` — отдельные структуры (`shared/config/Config.hpp`, автогенерация через `NLOHMANN_DEFINE_TYPE_NON_INTRUSIVE`, без ручного boilerplate). Серверный `config.json` остаётся в корне репозитория; клиентский теперь генерируется и читается рядом с исполняемым файлом клиента (`shared/platform/ExecutablePath.hpp` — кроссплатформенное определение своего расположения), а не из общего файла или рабочей директории. Оба файла автосоздаются со значениями по умолчанию, если отсутствуют.
- raylib собирается только для клиента (опция `GOBLINS_WITH_RAYLIB`, включается в `clients/desktop/CMakeLists.txt`) — сервер остаётся headless и не тянет графику/X11/OpenGL.
- В `NetworkServer::start()` добавлен вызов `ix::initNetSystem()` — обязателен на Windows (WSAStartup) перед открытием сокетов.
- `build.ps1`/`run.ps1` заменены на `build.bat`/`run.bat` — не требуют смены политики выполнения PowerShell-скриптов, работают из коробки в `cmd`.
- Добавлена подсветка тайла под курсором мыши в клиенте (с координатами в HUD).
- Добавлена настоящая пауза мира: `GameLoop.paused` (атомарный флаг), управляемый по сети через `NetworkServer` — клиент по клавише `P` шлёт `{"type":"toggle_pause"}`, сервер переключает паузу и рассылает `pause_state` всем подключённым клиентам (единый источник истины — на сервере, а не локальная догадка каждого клиента). Пауза настоящая: пока она активна, `GameLoop::tick()` не выполняет систем и не рассылает тики. Протокол дополнен полем `paused` в `world_snapshot` — новый клиент сразу видит текущее состояние.
- Добавлен слой почвы и воды: `SoilComponent` (влажность/каменистость/утрамбованность), `WaterComponent` (глубина) — по одному терраформирующему Entity на тайл (04_WorldModel.md — почва - это Entity, не свойство тайла). `TerrainGenerator` (core, vendored FastNoiseLite): heightmap на фрактальном шуме (fBm, OpenSimplex2) → Priority-Flood (Barnes et al., 2014) для заполнения впадин (пруды) → D8 flow accumulation по заполненному рельефу (реки, с возможностью "начинаться" за краем карты через случайный бонус на граничных клетках) → влажность через multi-source BFS (distance transform) от воды. Каменистость/утрамбованность подмешаны в heightmap как бугры — вода их физически огибает, поэтому в таких местах река не возникает без ручных исключений. `scatterBoulders` не ставит булыжники на воду.
- Все числовые параметры генерации террейна вынесены в конфигурацию (`ServerConfig::TerrainConfig`, поле `terrain` в `config.json`) — ни одно значение не зашито в `TerrainGenerator.cpp`. core остаётся независимым от JSON/конфигурации (07_TechStack.md, п.6): параметры описаны как plain-структура `core::TerrainParams`, server явно переносит в неё значения из своей конфигурации перед генерацией.
