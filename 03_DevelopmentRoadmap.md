# 03_DevelopmentRoadmap.md

# Назначение документа

Данный документ определяет последовательность разработки проекта.

Главной задачей является создание минимальной автономной симуляции (MVP), которая постепенно усложняется без изменения фундаментальной архитектуры.

Разработка ведётся от простых систем к сложным. Каждый следующий этап опирается только на уже реализованные возможности предыдущих этапов.

Проект не должен проектировать высокоуровневые механики раньше появления необходимой для них основы.

---

# Общие принципы разработки

Во время разработки необходимо придерживаться следующих правил.

## Простое раньше сложного

Любая сложная система должна появляться только после реализации всех необходимых низкоуровневых механизмов.

Например:

* сначала карта;
* затем ресурсы;
* затем растения;
* затем животные;
* затем разумные существа.

---

## Каждая стадия должна быть законченной

После завершения каждого этапа симуляция должна оставаться работоспособной.

Каждая новая возможность расширяет существующий мир, а не заменяет его.

---

## Минимальная достаточность

Каждая система сначала реализуется в самом простом виде.

Дополнительные возможности добавляются только после проверки базовой версии.

---

## Архитектура не изменяется

Все этапы используют одну архитектуру.

По мере развития проекта добавляются новые компоненты, системы и типы Entity, но фундаментальные принципы остаются неизменными.

---

## ИИ разрабатывается последним

Большинство поведения мира должно быть проверено до появления полноценного искусственного интеллекта.

На ранних этапах допускается использование простого временного ИИ.

---

# Этап 1. Основа симуляции

Цель этапа — создать минимальный мир, способный существовать самостоятельно.

Необходимо реализовать:

* карту;
* тайлы;
* игровое время;
* игровой цикл;
* Entity;
* ECS;
* системы симуляции.

Результат этапа:

Существует пустой мир, который способен выполнять игровые тики.

---

# Этап 2. Неодушевлённый мир

После появления основы симуляции добавляются объекты окружающей среды.

Необходимо реализовать:

* природные ресурсы;
* деревья;
* камни;
* воду;
* землю;
* размещение объектов на карте.

На данном этапе объекты не обладают поведением.

Результат этапа:

Существует статичный мир, содержащий природные объекты.

---

# Этап 3. Растения

На данном этапе появляются первые самостоятельно изменяющиеся объекты.

Необходимо реализовать:

* рост;
* размножение;
* постепенное изменение состояния;
* отмирание.

Растения должны существовать полностью автономно.

Результат этапа:

В мире появляются первые естественные процессы.

---

# Этап 4. Травоядные

Добавляются первые подвижные существа.

Необходимо реализовать:

* передвижение;
* поиск пищи;
* питание;
* размножение;
* смерть.

Поведение может использовать максимально простой временный ИИ.

Результат этапа:

Появляется простейшая пищевая цепочка между растениями и животными.

---

# Этап 5. Хищники

После появления травоядных добавляются хищники.

Необходимо реализовать:

* поиск добычи;
* преследование;
* охоту;
* питание;
* размножение;
* смерть.

Результат этапа:

В мире начинает формироваться простая экосистема.

---

# Этап 6. Разумные существа

После проверки работы экосистемы добавляются разумные существа.

Необходимо реализовать минимальный набор действий.

Например:

* перемещение;
* подбор предметов;
* перенос предметов;
* использование предметов;
* питание;
* отдых.

Разумные существа отличаются от остальных объектов только набором компонентов.

Результат этапа:

В мире появляются первые существа, способные осознанно взаимодействовать с окружающей средой.

---

# Этап 7. Общение

После появления разумных существ реализуется передача информации между ними.

Необходимо реализовать:

* передачу знаний;
* получение знаний;
* хранение знаний.

Общение не должно включать сложные социальные механики.

Его задача — обеспечить распространение информации внутри симуляции.

Результат этапа:

Знания начинают распространяться между персонажами естественным способом.

---

# Этап 8. Временный ИИ

На данном этапе реализуется первый модуль искусственного интеллекта.

Его целью является исключительно проверка архитектуры.

Временный ИИ может использовать простейшие алгоритмы, включая случайный выбор действий.

Он не должен содержать сложного планирования.

Результат этапа:

Становится возможной проверка взаимодействия симуляции с внешним модулем ИИ.

---

# Этап 9. Строительство

После проверки взаимодействия персонажей с миром появляется строительство.

Необходимо реализовать:

* выполнение работ;
* строительство объектов;
* завершение строительства.

Строительство должно использовать уже существующие механизмы симуляции.

Результат этапа:

Персонажи начинают изменять окружающий мир собственными действиями.

---

# Этап 10. Производство

После появления строительства добавляется производство.

Необходимо реализовать:

* преобразование ресурсов;
* производственные процессы;
* использование предметов;
* получение новых объектов.

Все процессы должны использовать единую систему Работы.

Результат этапа:

Персонажи получают возможность самостоятельно создавать новые предметы и материалы.

---

# Этап 11. Проектирование полноценного ИИ

Только после появления работающей симуляции начинается проектирование полноценного искусственного интеллекта.

Архитектура ИИ должна удовлетворять следующим требованиям:

* ИИ является полностью отдельным модулем.
* Мир не зависит от реализации ИИ.
* ИИ не имеет прямого доступа к объектам мира.
* Любое взаимодействие осуществляется только через интерфейсы.
* ИИ получает только ту информацию, которой обладает конкретный персонаж.
* Знания, умения и состояние персонажа являются частью симуляции и хранятся в компонентах мира.
* ИИ не может изменять мир напрямую.
* ИИ возвращает только принятое решение.
* Проверка возможности выполнения действия производится симуляцией.

Такая архитектура позволяет заменить любой алгоритм искусственного интеллекта без изменения остальных частей проекта.

В качестве реализации могут использоваться различные алгоритмы принятия решений, если они поддерживают единый интерфейс взаимодействия с симуляцией.

---

# Итоговая последовательность разработки

1. Основа симуляции.
2. Неодушевлённый мир.
3. Растения.
4. Травоядные.
5. Хищники.
6. Разумные существа.
7. Общение.
8. Временный ИИ.
9. Строительство.
10. Производство.
11. Проектирование полноценного ИИ.

Каждый следующий этап допускается начинать только после завершения предыдущего.

При необходимости отдельные этапы могут быть разбиты на более мелкие задачи без изменения общей последовательности разработки.
